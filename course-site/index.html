    How CSS worksComment fonctionne le CSS

    A CSS file is a list of rules. Each rule picks elements with a selector, then sets properties:

    Un fichier CSS est une liste de règles. Chaque règle choisit des éléments avec un sélecteur, puis définit des propriétés :

    SelectorSélecteurPicksSélectionne
    h1every <h1>tous les <h1>
    .cardevery element with class="card"tout élément avec class="card"

    When two rules disagree, the more specific selector wins (#id beats .class beats tag), and if they're equal, the one written last wins. That's the “cascade” in Cascading Style Sheets.

    Quand deux règles se contredisent, le sélecteur le plus spécifique gagne (#id bat .classe qui bat balise) ; à égalité, la règle écrite en dernier gagne. C'est la « cascade » de Cascading Style Sheets.

    Grid

    Grid works in two dimensions: you declare columns (and rows) and children drop into them. grid-template-columns: 270px 1fr means “a 270px sidebar, then all the remaining space” (fr = fraction of free space). For the cards, repeat(auto-fill, minmax(220px, 1fr)) means “as many 220px+ columns as fit”: responsive without any media query.

    Grid travaille en deux dimensions : tu déclares des colonnes (et des lignes) et les enfants s'y placent. grid-template-columns: 270px 1fr signifie « une barre latérale de 270px, puis tout l'espace restant » (fr = fraction de l'espace libre). Pour les cartes, repeat(auto-fill, minmax(220px, 1fr)) veut dire « autant de colonnes de 220px minimum que possible » : du responsive sans media query.

    Rule of thumb: flex for a row of things, grid for a page structure or a gallery. And always space siblings with gap rather than margins.

    Règle simple : flex pour une rangée d'éléments, grid pour une structure de page ou une galerie. Et espace toujours les éléments voisins avec gap plutôt qu'avec des marges.

    A card is a componentUne carte est un composant

    A component is a piece of HTML + CSS you repeat with different data. Design one card perfectly; the next step will stamp out 78 of them with JavaScript. Four CSS ideas make this card work:

    Un composant est un morceau de HTML + CSS que l'on répète avec des données différentes. Conçois une carte parfaite ; l'étape suivante en fabriquera 78 avec JavaScript. Quatre idées CSS font fonctionner cette carte :

    • position: relative on the photo box + position: absolute on the year: the year is placed relative to the photo's corners (left: 14px; bottom: 6px).

    Why a database?Pourquoi une base de données ?

    A JavaScript array lives inside one page: every visitor downloads all of it and you can only search it with code you write yourself. A database keeps the data in one place, on the server, and answers precise questions in one line of SQL (Structured Query Language): “who won the most?”, “which clubs?”, “how old was each winner?”.

    SQLite is a database that fits in a single file. No installation, no separate server: perfect for learning, and it powers every smartphone.

    SQLite est une base de données qui tient dans un seul fichier. Pas d'installation, pas de serveur séparé : parfait pour apprendre, et elle tourne dans tous les smartphones.

      There are two kinds of text. Interface text (buttons, labels) lives in a dictionary in app.js. Data text (descriptions, countries) lives in the database, in pairs of columns: description_en/description_fr, nationality/nationality_fr.
      
    
      Il y a deux sortes de textes. Le texte d'interface (boutons, libellés) vit dans un dictionnaire dans app.js. Le texte des données (descriptions, pays) vit dans la base, en paires de colonnes : description_en/description_fr, nationality/nationality_fr.
