Why a database?Pourquoi une base de données ?

A JavaScript array lives inside one page: every visitor downloads all of it and you can only search it with code you write yourself. A database keeps the data in one place, on the server, and answers precise questions in one line of SQL (Structured Query Language): “who won the most?”, “which clubs?”, “how old was each winner?”.

Un tableau JavaScript vit dans une page : chaque visiteur le télécharge en entier et tu ne peux le fouiller qu'avec ton propre code. Une base de données garde les données à un seul endroit, sur le serveur, et répond à des questions précises en une ligne de SQL (Structured Query Language) : « qui a gagné le plus ? », « quels clubs ? », « quel âge avait chaque lauréat ? ».

SQLite is a database that fits in a single file. No installation, no separate server: perfect for learning, and it powers every smartphone.

SQLite est une base de données qui tient dans un seul fichier. Pas d'installation, pas de serveur séparé : parfait pour apprendre, et elle tourne dans tous les smartphones.

Two tables, not oneDeux tables, pas une

Messi won 8 times. In a single big table, his name, country, birth year and photo would be copied 8 times, and a typo fixed in one row would stay wrong in the 7 others. So we split: players holds each person once; awards holds each trophy and points to its winner with player_id. That pointer is a foreign key; the unique id it points to is the primary key.

Messi a gagné 8 fois. Dans une seule grande table, son nom, son pays, son année de naissance et sa photo seraient copiés 8 fois, et une faute corrigée dans une ligne resterait fausse dans les 7 autres. On sépare donc : players contient chaque personne une seule fois ; awards contient chaque trophée et désigne son lauréat avec player_id. Ce pointeur est une clé étrangère ; l'id unique qu'il désigne est la clé primaire.

    Requests and responsesRequêtes et réponses

    The web is a conversation. The browser sends a request (a method like GET, a path, maybe a query string after ?); the server sends back a response (a status code and a body). Our body will be JSON: the same notation as JavaScript objects, as text.

    Le web est une conversation. Le navigateur envoie une requête (une méthode comme GET, un chemin, éventuellement des paramètres après ?) ; le serveur renvoie une réponse (un code de statut et un corps). Notre corps sera du JSON : la même notation que les objets JavaScript, sous forme de texte.

    StatusMeansSignifie

    Never glue user text into SQLNe colle jamais le texte de l'utilisateur dans du SQL

    `… WHERE player = '${q}'` looks harmless until someone searches for ' OR 1=1 -- and rewrites your query. That's SQL injection. Always write placeholders (@q or ?) and pass the values separately to .all(params): the database then treats them as data, never as code.

    `… WHERE player = '${q}'` semble inoffensif jusqu'à ce que quelqu'un cherche ' OR 1=1 -- et réécrive ta requête. C'est l'injection SQL. Écris toujours des marqueurs (@q ou ?) et passe les valeurs séparément à .all(params) : la base les traite alors comme des données, jamais comme du code.
